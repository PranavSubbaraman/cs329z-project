# #1594: Cross entropy zeroes the ignore_index rows of its input when no gradient is needed
state: open
url: https://github.com/linkedin/Liger-Kernel/issues/1594
created: 2026-11-03T15:03:38Z

### 🐛 Describe the bug

`liger_cross_entropy` on the default Triton path writes zeros over every row of the input whose target is `ignore_index`, even when the input doesn't require grad. In `liger_cross_entropy_kernel` (`ops/cross_entropy.py:104-108`) the `y == ignore_index` branch stores 0.0 with no `HAS_GRADIENTS` check, while the gradient pass for the other rows sits behind `if HAS_GRADIENTS:` (line 206). The CuTe DSL kernel only writes under `HAS_GRAD` (`ops/cutedsl/ops/cross_entropy.py:512`).

This isn't #272, which is about the gradient written during a forward that needs one. Here nothing needs a gradient and the caller's tensor still changes. transformers' `ForCausalLMLoss` calls `logits.float()` first, so bf16 logits get a copy, but fp32 logits are the model's own tensor.

We saw it in [Halo](https://github.com/whitecircle/halo) on a tiny model whose forward returns fp32 logits, Liger 0.8.4 on a B300, one run each way: in eval, rows with label -100 came back as zeros, labelled rows were byte-identical, and with Liger off nothing changed. A `preprocess_logits_for_metrics` or `compute_metrics` that reads logits at ignored positions gets zeros.

A fix could be to put that store behind `if HAS_GRADIENTS:`. I can send a PR.

### Reproduce

```python
import torch

from liger_kernel.transformers.functional import liger_cross_entropy

logits = torch.randn(4, 8, device="cuda")
target = torch.tensor([1, -100, 2, -100], device="cuda")
before = logits.clone()
with torch.no_grad():
    liger_cross_entropy(logits, target)
print("rows changed", (logits != before).any(dim=1).tolist())
print("ignored rows all zero", (logits[target == -100] == 0).all().item())
```

```
rows changed [False, True, False, True]
ignored rows all zero True
```
